# 收到通知該怎麼辦

寫給網站的老闆和店長，不需要懂程式。建議印出來，或存在手機記事本裡。（[English](when-an-alert-arrives.md)／[日本語](when-an-alert-arrives.ja.md)）

## 先看這三件事

1. **看等級**。【注意】＝有空時確認一下；【緊急】＝現在就處理，不要等到明天。
   （平常只有【緊急】會讓手機響；【注意】和每週報平安會安靜地出現在聊天室裡。）
2. **問一句「是不是我們自己做的？」** 大部分的【注意】都是自己人：剛上傳更新、店員換手機、今天退款比較多。問一下當事人，是的話就結束了。
3. **不是自己人做的，就照下面對應的那一段做。** 不確定的時候，當成「不是」來處理。

> 有一件事千萬不要做：**不要因為想趕快恢復正常，就直接把可疑的檔案刪掉了事。**
> 檔案是證據，刪掉之後就查不出對方是怎麼進來的，下次還會再進來。

---

## 【注意】後台登入失敗太多次

**意思**：有人（通常是自動程式）在猜你後台的密碼。網站放在網路上，這種事每天都有，被猜不等於被猜中。

**怎麼做**

- 確認每個後台帳號的密碼都夠長（12 個字以上）、而且沒有跟別的網站共用。
- 把「兩步驟驗證」打開，尤其是訊息裡點名的那幾個帳號。
- 如果同一個 IP 一直來，請主機商或工程師把它擋掉。
- 帳號名稱叫 `admin`、`test` 這種最容易被猜，可以的話改掉。

## 【注意】後台帳號從新的裝置和網路登入

**意思**：這個帳號登入成功了，但用的瀏覽器和網路都是以前沒見過的。

**怎麼做**

- 直接問帳號的主人：「剛剛是你登入的嗎？」換手機、出門用行動網路，都會出現這則。
- **不是本人**：馬上改這個帳號的密碼 → 把這個帳號所有裝置登出 → 看這個帳號登入之後做了什麼（改了什麼設定、看了哪些資料、有沒有退款或改價）。

## 【緊急／注意】後台帳號有變動

**意思**：有人新增或刪除了後台帳號、改了權限、改了密碼或 Email、關掉了兩步驟驗證。

**怎麼做**

- 問團隊：這是誰做的？有人承認就沒事。
- **沒有人承認**：先把那個帳號停用（不要刪），再把所有管理員的密碼都換掉，然後檢查最近的後台操作紀錄。
- 多出來的陌生帳號，是入侵者留給自己下次用的門。

## 【注意】主機上的程式檔有變動

**意思**：網站的程式有新增、修改或刪除。

**怎麼做**

- 你或工程師今天有上傳更新嗎？有，而且列出來的檔案對得上，就不用理會。
- **今天沒有人上傳任何東西**：這就是出事的訊號，請照下面【緊急】那一段處理。
- 檔案對不上（你只改了一支，卻列了十支）也要問清楚。

## 【緊急】主機上可能有後門程式

**意思**：出現了「長得像後門」的檔案，或是上傳圖片的資料夾裡出現了程式。這是最需要馬上處理的一種。

**照順序做**

1. **先確認是不是自己人放的**（問工程師）。不是，往下做。
2. **把網站切到維護模式**或暫時關站。多開一分鐘，對方就多一分鐘。
3. **不要刪檔**。請工程師把訊息裡列的檔案另外複製一份留存，再從網站上移走。
4. **用乾淨的備份還原**。「乾淨」是指出事之前的備份；不確定是哪一天出的事，就往更早的找。
5. **全部的密碼和金鑰都換掉**：後台、主機管理介面、資料庫、FTP、金流、LINE、寄信服務。對方進得來，就可能都看過了。
6. **找出是怎麼進來的**再重新開站：太久沒更新的系統或外掛？沒有檢查的上傳表單？被猜中的密碼？沒找到原因就開站，等於把門再打開一次。
7. 如果網站有會員資料或訂單資料，請確認資料有沒有被看到或帶走，並依照你所在地的法規決定要不要通知客人和主管機關。
   在台灣：個資法第 12 條和施行細則第 22 條要你「即時」通知受影響的客人（被侵害的事實和已採取的措施）；
   網路零售商品的業者另有數位發展部的規定，危及營運或大量客人權益的事故，要在知悉後 72 小時內通報。
   時間從「知悉」起算，收到這則通知的那天就可能是起點，請盡早問律師或會計師（整理在 README 的「出事時的法定通知」）。

**訊息裡寫「內容變了，修改時間卻被調回原樣」是什麼意思**

有人改了那支程式，還特地把檔案的「修改時間」調回原本的樣子，讓它看起來沒被動過。
正常上傳更新不會這樣，所以不管改了什麼內容都標成緊急。先問工程師是不是用了什麼特別的工具上傳；不是的話照上面 1～7 步做。

**訊息裡寫「→ 已改名為 …」是什麼意思**

你們有打開「自動隔離」。上傳資料夾裡新出現的那支程式，已經被自動改了檔名，主機不會再執行它。檔案沒有刪，還在原來的資料夾裡。

- 這只是先把門擋住。上面 1～7 步一樣要做：對方是怎麼把檔案放進來的，還沒有解決。
- 改過名的檔案不要刪，留給工程師查。
- 如果確定是自己人放的：請工程師把檔名改回去，並且把那個資料夾從「上傳資料夾」的設定裡拿掉，不然下次檢查又會被改名。
- 訊息寫「想自動改名但失敗了」：那支檔案還能執行，請當成沒有隔離，馬上處理。

## 【緊急】檔案指紋紀錄不見了／偵測紀錄被清空

**意思**：這套偵測自己的紀錄被清掉了，而且不是你們下的指令。入侵者想讓監控失效時，常常會這樣做。

**怎麼做**

- 先問工程師：有沒有搬過主機、清過資料夾、重裝過？有就沒事。
- 沒有：當成「主機上可能有後門程式」來處理（上面那一段）。這段時間被改了什麼，偵測已經列不出來，只能拿備份來比對。

## 【注意】檔案基準被手動重設

**意思**：有人下了「把目前的檔案都當成正常」的指令。

**怎麼做**：問工程師是不是他做的（大改版之後常會這樣做）。不是的話，等同上一段。

## 【注意】檔案指紋已升級成 SHA-256

**意思**：這套偵測剛更新過，把記錄檔案用的「指紋」換成比較新的算法。換之前每一支檔案都先跟舊指紋對過，沒變的才安靜換新。

**怎麼做**

- 問工程師：最近有更新這套偵測嗎？有，這則就是更新後的說明，只會出現一次，不用處理。
- **沒有人更新過卻收到**：代表有人把紀錄換成舊格式，照「檔案指紋紀錄不見了」那一段處理。

## 【注意】防火牆擋下很多次

**意思**：有人在大量試探你的網站，而且被擋住了。這是防火牆有在工作的證明。

**怎麼做**

- 自己用手機開一下網站、下一張測試訂單，確認客人還是能正常使用。
- 同一個 IP 持續不斷，可以請主機商或 CDN 直接封鎖。
- 這則如果常常出現，請工程師看看被試探的是哪個功能，那裡值得多留意。

## 【注意】退款／取消訂單／調整儲值金異常

**意思**：短時間內有很多筆人工退款、取消，或是金額特別大的一筆。

**怎麼做**

- 直接問訊息裡寫的那位操作者。活動結束、系統出錯補償，都會有這種情況。
- **他說不是他做的**：當成他的帳號被盜（見「從新的裝置登入」那一段），並且把那幾筆交易逐一核對。

## 【緊急】網頁開始用到別的網站

（工程師有設定「網頁監看」才會收到。）

**意思**：你的某一頁開始載入一個以前沒用過的外站程式、嵌入外站的畫面、把客人在表單裡填的資料送到別的網站，或是把客人轉到別的網站。
訊息裡的網域寫成 `cdn-evil[.]example` 是故意的，**不要點開**。

**怎麼做**

- 先問工程師和同事：今天有沒有人加了客服聊天、金流、分析或廣告工具？有，而且名字對得上，就沒事——請工程師把它加進允許清單。
- **沒有人加過**：當成有人改了網站設定或資料庫，想偷客人的刷卡資料或把客人導走。如果那一頁會收款或填個人資料，
  請工程師馬上把那一頁（或整個商店）先關掉，找出那段程式是從哪裡來的（常見是「頁尾／頁首自訂程式碼」的設定或某篇文章）並拿掉，
  然後照「主機上可能有後門程式」那一段做：換密碼、查對方怎麼進來、確認哪些客人可能受影響。

## 【緊急】網頁給搜尋引擎看的，跟你看到的不一樣

**意思**：Google 的爬蟲、或從 Google 搜尋點進來的客人，會拿到你自己打開網站時看不到的連結或轉址。
這是博弈、垃圾連結入侵躲過老闆的典型手法；放著不管，Google 搜尋結果可能出現賭場標題，或直接警告客人別點進來。

**怎麼做**

- 不要自己去點那些連結。請工程師在資料庫（文章、設定、頁尾）和程式裡搜尋訊息中的網域並清掉，然後照「主機上可能有後門程式」那一段做。
- 清乾淨之後，請工程師到 Google Search Console 看「安全性問題」，並要求 Google 重新審查。

## 【注意】網頁上多了連往別的網站的連結

**意思**：監看的網頁多了一個以前沒有的對外連結，所有人都看得到。

**怎麼做**：是你們自己加的嗎（新文章、合作夥伴、社群連結）？是就不用理會。沒有人加過的話，請工程師看一下那一頁：連結也可能用上面那種方式被塞進來。

## 訊息最後一行「🛑 不是你們做的、又聯絡不到人？按這裡把後台鎖住…」

（工程師有設定「緊急煞車」才會出現。Telegram 上是訊息下面的「🛑 把後台鎖住 4 小時」按鈕，Discord 上是最後一張卡片裡的連結。）

**什麼時候按**：上面那則是「緊急」，不是你或同事做的，而且聯絡不到工程師。點開連結、按頁面上的按鈕，
後台就會鎖住幾個小時——任何人都不能用，包括闖進來的人和你們自己的同事——客人照常購物。只點開連結不會有任何動作，要按按鈕才會鎖。
頁面如果寫「這個連結已經換新了」，代表後來又有新的「緊急」通知：請用最新那一則裡的連結（只有最新的連結能用，預設 12 小時內有效）。

接著繼續聯絡工程師。只有他能在主機上提早解鎖。拿不定主意的時候，按下去是比較安全的那一邊：最壞的結果是後台幾個小時不能用。

## 【緊急】後台已經鎖住

**意思**：有人按了緊急煞車（訊息會寫時間和從哪個 IP 按的），或工程師在主機上鎖住了後台。

**怎麼做**：是你按的就不用再做什麼，等工程師處理。**你們這邊沒有人按**：代表有人看得到你的通知訊息，或已經在主機上，今天就要告訴工程師。

## 【注意】開始上傳預告／上傳預告延長了

**意思**：剛剛有人在主機上跑了 `--expect`。到訊息寫的時間為止，一般的程式變動會收集起來、結束後合成一則；內容像後門的照樣立刻通知。

**怎麼做**：工程師（或自動部署）現在正在更新網站嗎？是就沒事。**你們這邊沒有人預告要更新**：可能有人進了主機、想趁這段時間偷改程式，馬上告訴工程師，照「主機上可能有後門程式」那一段做。

## 【注意】預告的更新時段內，程式有這些變動

**意思**：工程師上傳更新之前跑了 `--expect`。那段時間的程式變動沒有一支一支通知，而是收集起來，在這一則一次列出。

**怎麼做**：訊息寫的那段時間，真的有在更新網站嗎？有就沒事。**那段時間其實沒有人更新**：代表有人進了主機，用預告來掩護他改的檔案，照「主機上可能有後門程式」那一段做。

## 訊息開頭寫「⏱ 補發：這則是 … 的通知」

**意思**：這則通知其實是更早發生的事。當時所有管道都發不出去（LINE 當機或每月則數用完，又沒設 Telegram、Discord 或 Email…），所以先留著，現在才補上。

**怎麼做**

- 看訊息裡寫的原本時間，照那則通知的內容處理：事情是那個時間發生的，不是現在。
- 常常收到補發，代表通知管道不穩：請工程師看 LINE 的每月則數夠不夠，並確認有設第二個管道（Email、Telegram 或 Discord）。

## 【每週報平安】

**意思**：沒事。這則每週一次，告訴你偵測還活著。

**要注意的反而是沒收到的時候**：超過一週沒有這則，代表檢查沒在跑（排程停了、LINE 金鑰過期、主機重灌之後沒裝回去）。請工程師看一下。
另外，訊息裡的「紀錄從哪一天開始」如果突然變成最近的日期，代表紀錄被重設過，要問清楚原因。

### 訊息裡的「程式總指紋」怎麼看

那一串字（像 `3f9a-0c1d-77b2-e4a8`）是把網站所有程式檔算出來的。任何一支程式被動過，這串字就會變。
它留在你的 LINE 裡，闖進主機的人改不到，所以**這些報平安訊息不要刪**。

看括號裡寫什麼就好：

| 訊息寫 | 你要做的 |
|---|---|
| 跟上次報平安一樣 | 不用做什麼。這一週程式沒被動過 |
| 上次是 xxxx，這段時間通知過 N 次程式變動 | 回想那 N 次是不是都是自己人上傳的。是，就沒事 |
| 上次是 xxxx，有 N 次變動只寫進紀錄、沒有發通知 | 請工程師看一下紀錄。多半是網站自己改寫的檔案，或那天通知太多被擋下 |
| 開頭有 ⚠、寫「沒有任何程式變動的紀錄」 | **當天處理。** 程式變了，偵測卻沒記到，代表偵測的紀錄可能被人改過。照「主機上可能有後門程式」那一段做 |

想自己確認，往上滑到上一則報平安，把兩串字對一下就知道訊息有沒有說實話。

### 訊息裡的「這個月 LINE 大約發了幾則」

LINE 官方帳號每個月能主動發的訊息有上限（看你們的方案）。這一行是偵測每週順便問 LINE 的，數字包含同一個官方帳號發的所有訊息（發給客人的活動訊息也算）。

- 沒有 ⚠：不用做什麼。
- **有 ⚠「快用完了」或「已經用完」**：用完之後 LINE 就發不出去，資安通知也一樣。兩件事擇一或都做：到 LINE 官方帳號後台把方案升上去；請工程師確認有設定第二個管道（Email、Telegram 或 Discord；設了的話，LINE 發不出去會改走那裡）。
  Telegram 和 Discord 都免費；設定 `line_min_level => 2` 可以讓 LINE 只發緊急的。

### 訊息裡多了一行「⚠ 發這些通知的 LINE 官方帳號大約有 N 個好友」

**意思**：通知是從一個很多人追蹤的官方帳號發出來的，多半就是客人加好友的那一個。它的金鑰放在網站主機上，萬一主機被入侵，對方就能用你們店的帳號發訊息給所有這些人。

**怎麼做**：另開一個只發通知的 LINE 官方帳號（只有你和幾位同事加好友），請工程師把通知改成用它發。客人的帳號留給客人用。

### 訊息裡的「通知管道正常：…」或「⚠ 有通知管道現在不能用」

**意思**：通知能送的地方不只一個時（例如 Telegram 加上 LINE 當備援），偵測每週會順便確認每個管道都還能用。不發訊息，只是查詢。

- 「通知管道正常」：不用做什麼。
- **「⚠ 有通知管道現在不能用：…」**：括號裡寫了原因（機器人被封鎖、Webhook 被刪、有收件人封鎖了 LINE 帳號……）。
  通知還是會走其他管道送到，但備援已經壞了，請工程師這週內修好（他跑 `--test-all` 就會看到該怎麼修）。
  寫「有收件人封鎖了帳號」時，先問問同事是不是有人把通知帳號封鎖或刪掉好友了，加回來就好。

### 訊息裡多了一行「⚠ 外部報到網址連續失敗」

**意思**：你們有設定「排程停了由外部服務通知」，但那個報到網址一直連不上。偵測本身還在跑，只是萬一排程停了，沒有人會通知你。

**怎麼做**：請工程師檢查設定裡的報到網址（是不是貼錯、那個服務的帳號還在不在）。

## 外部服務（不是 LINE）通知你「排程沒有報到」

**意思**：如果你們有設定外部報到，這則會從那個服務寄來（通常是 Email）。它是說：網站的定時檢查已經超過時間沒有回報了。

**怎麼做**

- 先用手機開一下網站。網站也打不開，就是主機出問題，找主機商。
- 網站正常，只有檢查停了：請工程師看排程（最近有沒有搬主機、改過設定、主機商維護）。
- 沒有人動過排程卻停了，要當一回事：把排程關掉，也是讓偵測失效的一種方法。

## 平常就先準備好

出事的時候才找這些，通常來不及：

- **備份**：每天自動備份，而且至少有一份不放在同一台主機上。半年做一次還原演練，確認備份真的能用。
- **一張清單**：主機商的客服電話、工程師的聯絡方式、各個服務的管理網址。放在手機裡，不要只放在網站後台。
- **密碼**：每個人一個帳號、不共用；全部開兩步驟驗證；離職當天就停用。
- **更新**：系統和外掛有安全更新就裝。大部分的入侵用的都是早就有修補的舊漏洞。
