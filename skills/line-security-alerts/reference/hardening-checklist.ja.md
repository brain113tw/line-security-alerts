# 予防チェックリスト：アラートが鳴る前にやっておくこと

このパッケージがするのは「何か起きたら知らせる」ことです。このリストはもう半分、つまり「そもそも起きにくくする」ためのものです。
どんな守りも破られることがあるので、両方が必要です。

（いくつかの項目は、最初に公開したあと読者が提案してくれたものです。ありがとうございます。）[English](hardening-checklist.md)／[中文版](hardening-checklist.zh-TW.md)

> この日本語版は翻訳です。誤りがあれば Issue でお知らせください。

## 1. どれも 10 分ほど。まずこれから

**1. アップロード用フォルダでプログラムを実行させない**

お客さんやスタッフが画像をアップロードするフォルダには、画像と文書だけがあるべきです。いちばんよくある侵入方法は、画像に見せかけたプログラムをアップロードして、それを開くことです。
そのフォルダを「中のプログラムファイルは一切開かせない」設定にすれば、この手口は使えなくなります。

Apache（多くのレンタルサーバー）なら、そのフォルダに `.htaccess` を置きます：

```
<FilesMatch "\.(php\d?|phtml|pht|phar|inc|cgi|pl|py|sh)$">
    Require all denied
</FilesMatch>
```

nginx には `.htaccess` がないので、レンタルサーバー会社か開発者に、設定でそのフォルダに同じことをしてもらってください。
設定したら一度自分で試します：テスト用の `.php` を置いてブラウザで開き、拒否されれば成功です。試したら削除してください。
このパッケージの「アップロード用フォルダにプログラムがある」アラートは、この項目の予備です。万一この設定が誰かに変えられても、気づけます。

**2. 管理画面のアカウントはすべて 2 段階認証（またはパスキー）をオンに**

1 人 1 アカウントで、共有しないこと。アカウント名を `admin` にしないこと。辞めた人のアカウントはその日に停止すること。

**3. バックアップはサーバーの外に置き、実際に一度戻してみる**

戻してみたことのないバックアップは、本当にあるかどうかわからないのと同じです。

**4. サーバーの外から見る 2 つのサービス**

- サイトが開けるか：外部のサイト監視サービスを使う。
- 定期実行がまだ動いているか：cron チェックインサービスの URL を、このパッケージの `ping_url` に入れる。

**5. システムやプラグインのセキュリティ更新は入れる**

侵入のほとんどは、とっくに修正済みの古い穴を使っています。

## 2. 管理画面の前にもう 1 枚扉を付ける

2 段階認証が守るのは「アカウント」です。パスワードを当てられてもログインできません。
扉をもう 1 枚付けると守れるのは「管理画面全体」です。通過できない人は、管理画面のどのページにも——万一穴があるページにも——たどり着けません。両者はぶつからないので、両方あってかまいません。

**方法 A：サイトの前に置いたサービスで本人確認をする**（Cloudflare Access など）

サイトがもともとこの種のサービスの後ろにあるなら、設定を 1 つ足すだけです：管理画面の URL には、先に本人確認を通るよう指定します（Google アカウントなども使え、確認メールが必須とは限りません）。
注意点：

- **本当の IP を取り戻す。** つなぐと、サーバーから見た接続元はそのサービスの IP になります。サーバーやプログラムを、サービスが付けてくる本当の IP を読むように変え、しかも接続が本当にそのサービスから来たときだけ信じるようにしてください。
  これをしないと、このパッケージの通知に出る IP が全部同じになり、「同じ IP から何度も」の判定もおかしくなります。`loginFailed()` や `firewallBlocked()` に渡す IP は、取り戻したあとのものにしてください。
- **元のサーバーに鍵をかける。** サーバーの本当のアドレスを知っている人は、前の層を素通りして直接つなげます。管理画面はそのサービス経由の接続しか受け付けないようにしてください。
- **機械が呼び出す URL は通す。** 決済、LINE、電話システムなど、ほかのシステムから呼び出される URL はふさがないこと。
- まずテスト環境で行い、支払い、メッセージ通知、定期実行をすべて試してから本番に入れてください。

**方法 B：サーバー自体の「フォルダのパスワード保護」を使う**

多くのレンタルサーバーの管理画面にある機能です（管理画面のフォルダにユーザー名とパスワードを設定し、どのページを開く前にもブラウザが入力欄を出す）。ドメインの設定は変えずに済み、合わなければ外すだけです。
注意点：

- パスワードは長いランダムなものに。この扉自体には、たいてい「何回か間違えたらロック」の仕組みがありません。
- 同じように、機械が呼び出す URL は通してください。
- **本物のスマホで試す。** スマホのブラウザ、チャットアプリの中のブラウザ、ホーム画面に追加した Web アプリでは、この入力欄への対応がまちまちです。スタッフが毎日スマホで管理画面を開くなら、試してから全体で有効にしてください。

## 3. サーバーを丸ごと自分で管理している場合（VPS）

- リモートログイン（SSH）を全世界に開けない：鍵でのログインだけにする、ファイアウォールで接続元を絞る、またはふだんは閉じておき、必要なときにサーバー会社のコンソールから入る。
- レンタルサーバーを借りている場合、この層には手が届きません。サーバー会社が管理しているので、やっているか聞いてみてください。

## 4. アップロード機能の発展的なやり方

サイトの前に小さなプログラムを動かせるサービスがあるなら、アップロードをまずそこに通すこともできます：外側でサイズと形式を確かめ、合格したものだけをサーバーへ渡す。サーバー側は、リクエストが本当にその層から来たかを確かめ、自分でももう一度チェックする。
これは層が 1 つ増えるだけで、唯一の守りではありません。「画像に見える」かどうかのチェックでは、本物の画像の後ろにプログラムを隠す手口は防げないので、本当の保険はやはり 1 つ目の項目です。

## このリストが代わりにならないもの

検知です。上の項目はどれも事故が起きる確率を下げますが、どれも保証にはなりません。だから、起きたその日に知らせてくれるものが、やはり必要です。
