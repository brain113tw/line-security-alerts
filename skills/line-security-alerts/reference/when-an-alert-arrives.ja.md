# 通知が届いたら

サイトの店主や店長向けです。プログラムの知識はいりません。印刷するか、スマホのメモに保存しておいてください。
（[English](when-an-alert-arrives.md)／[中文版](when-an-alert-arrives.zh-TW.md)）

> この日本語版は翻訳です。誤りがあれば Issue でお知らせください。
> 通知の文面は英語（または繁体字中国語）で届きます。各見出しのかっこ内が、届くメッセージの英語のタイトルです。

## まずこの 3 つ

1. **レベルを見る**。【Notice】＝手が空いたときに確認。【URGENT】＝今すぐ対応。明日まで待たないこと。
2. **「自分たちがやったこと？」と聞く**。【Notice】のほとんどは身内です：更新をアップロードした、スタッフがスマホを替えた、今日は返金が多かった。本人に聞いて、そうなら終わりです。
3. **身内でなければ、下の該当する項目のとおりに対応する**。わからないときは「身内ではない」として扱ってください。

> 絶対にしてはいけないことが 1 つあります：**早く元に戻したいからといって、怪しいファイルを削除して終わりにしないこと。**
> ファイルは証拠です。消してしまうと相手がどうやって入ってきたのかわからなくなり、また入ってきます。

---

## 【Notice】管理画面のログイン失敗が多すぎる（Too many failed admin logins）

**意味**：誰か（たいていは自動プログラム）が管理画面のパスワードを当てようとしています。ネットにあるサイトなら毎日のように起きることで、狙われた＝破られた、ではありません。

**対応**

- 管理画面のアカウントのパスワードが、どれも十分に長く（12 文字以上）、ほかのサイトと使い回していないか確認する。
- 「2 段階認証」をオンにする。特にメッセージに名前が出たアカウント。
- 同じ IP から何度も来るなら、レンタルサーバー会社か開発者にブロックしてもらう。
- `admin`、`test` のようなアカウント名は真っ先に狙われます。変えられるなら変える。

## 【Notice】管理者が新しい端末・ネットワークからログインした（Admin "…" signed in from a new device and network）

**意味**：ログインには成功しましたが、使われたブラウザとネットワークがどちらも、これまで見たことのないものでした。

**対応**

- アカウントの持ち主に直接聞く：「さっきログインしたのはあなた？」スマホを替えた、外出先でモバイル回線を使った、でもこの通知が出ます。
- **本人ではない**：すぐにそのアカウントのパスワードを変える → そのアカウントをすべての端末からログアウトさせる → ログイン後に何をしたか（設定の変更、見たデータ、返金や価格の変更）を確認する。

## 【URGENT／Notice】管理者アカウントが変更された（Admin account changed）

**意味**：管理者アカウントが追加・削除された、権限・パスワード・メールアドレスが変更された、2 段階認証がオフにされた、のどれかです。

**対応**

- チームに「誰がやった？」と聞く。名乗り出る人がいれば問題ありません。
- **誰も名乗り出ない**：まずそのアカウントを停止し（削除はしない）、管理者全員のパスワードを変え、最近の管理画面の操作記録を確認する。
- 見覚えのないアカウントは、侵入者が次に使うために残した裏口です。

## 【Notice】サーバーのプログラムファイルが変わった（Code files changed on the server）

**意味**：サイトのプログラムが追加・変更・削除されました。

**対応**

- 今日、あなたか開発者が更新をアップロードしましたか？　していて、一覧のファイルとも合っているなら、気にしなくて大丈夫です。
- **今日は誰も何もアップロードしていない**：これが異常のサインです。下の【URGENT】の項目のとおりに対応してください。
- ファイルが合わない（1 本しか変えていないのに 10 本載っている）ときも、理由を確認してください。

## 【URGENT】サーバーにバックドアがあるかもしれない（Possible backdoor on the server）

**意味**：「バックドアに似た」ファイルが現れたか、画像をアップロードするフォルダにプログラムが現れました。いちばん急いで対応すべきものです。

**この順番で**

1. **身内が置いたものではないか確認する**（開発者に聞く）。違うなら次へ。
2. **サイトをメンテナンスモードにする**か、一時的に閉じる。開けている 1 分 1 分が相手の時間になります。
3. **削除しない**。メッセージに載っているファイルを開発者に別の場所へコピーして保管してもらい、そのうえでサイトから取り除く。
4. **きれいなバックアップから戻す**。「きれい」とは、異常が起きる前のバックアップのことです。いつ起きたかわからなければ、もっと前のものを探します。
5. **パスワードとキーを全部変える**：管理画面、レンタルサーバーの管理画面、データベース、FTP、決済サービス、LINE、メール送信サービス。入られたのなら、全部見られたと考えてください。
6. **どうやって入られたかを突き止めてから**サイトを再開する：長く更新していないシステムやプラグイン？　何もチェックしていないアップロードフォーム？　当てられたパスワード？　原因がわからないまま再開すれば、また扉を開けることになります。
7. 会員情報や注文情報があるサイトなら、見られたり持ち出されたりしていないかを確認し、自分の地域の法令に従って、お客さんや監督官庁への報告が必要か判断してください。

**メッセージに「its content changed but its modification time was put back」（中身が変わったのに更新日時が元に戻されている）とあったら**

誰かがそのプログラムを書き換えたうえで、ファイルの「更新日時」をわざわざ元に戻し、触っていないように見せかけています。
ふつうのアップロードではこうはならないので、何が変わったかにかかわらず URGENT になります。まず開発者に、特殊なツールでアップロードしたかを聞いてください。違うなら上の 1〜7 のとおりに対応します。

**メッセージに「→ renamed to …」（…に名前を変更）とあったら**

「自動隔離」をオンにしています。アップロード用フォルダに新しく現れたプログラムは自動で名前が変えられ、サーバーはもう実行しません。ファイルは削除されておらず、同じフォルダに残っています。

- これはひとまず扉を押さえただけです。上の 1〜7 は同じように必要です。ファイルがどうやって置かれたかは、まだ解決していません。
- 名前を変えたファイルは削除せず、開発者が調べられるように残してください。
- 本当に身内が置いたものなら：開発者に名前を戻してもらい、そのフォルダを「アップロード用フォルダ」の設定から外してもらってください。そうしないと次のチェックでまた名前が変わります。
- メッセージに「Automatic renaming was tried and failed」（自動での名前変更に失敗）とあれば：そのファイルはまだ実行できます。隔離はなかったものとして、すぐに対応してください。

## 【URGENT】ファイルの指紋の記録が消えた／監視の記録が消された（The file fingerprints have disappeared／The monitoring records were wiped）

**意味**：この監視自身の記録が消されました。しかも、あなたたちが指示したものではありません。侵入者が監視を無効にしたいとき、よくこうします。

**対応**

- まず開発者に聞く：サーバーの引っ越し、フォルダの整理、再インストールなどをしましたか？　していれば問題ありません。
- していない：上の「バックドアがあるかもしれない」として対応してください。この間に何が変わったかは監視ではもう一覧にできないので、バックアップと比べるしかありません。

## 【Notice】ファイルの基準が手動でリセットされた（The file baseline was reset by hand）

**意味**：誰かが「今のファイルを全部正常とみなす」という操作をしました。

**対応**：開発者がやったかを聞いてください（大きな改修のあとによくやります）。違うなら、ひとつ上の項目と同じです。

## 【Notice】ファイルの指紋が SHA-256 に移行された（File fingerprints upgraded to SHA-256）

**意味**：この監視が更新され、ファイルを記録する「指紋」の計算方法が新しくなりました。切り替える前に、すべてのファイルを古い指紋と照合し、変わっていないものだけを黙って移行しています。

**対応**

- 開発者に聞く：最近この監視を更新しましたか？　していれば、これは更新後に一度だけ届くお知らせです。何もしなくて大丈夫です。
- **誰も更新していないのに届いた**：誰かが記録を古い形式のものに差し替えたということです。「ファイルの指紋の記録が消えた」の項目のとおりに対応してください。

## 【Notice】ファイアウォールが大量にブロックしている（The firewall is blocking a lot of requests）

**意味**：誰かがあなたのサイトを大量に探っていて、ブロックされています。ファイアウォールが仕事をしている証拠です。

**対応**

- 自分のスマホでサイトを開き、テスト注文をして、お客さんが普通に使えることを確認する。
- 同じ IP が続くなら、レンタルサーバー会社か CDN にブロックしてもらう。
- この通知が頻繁に来るなら、開発者にどの機能が狙われているか見てもらう。そこは注意する価値があります。

## 【Notice】返金・キャンセル・残高調整がいつもと違う

**意味**：短い時間に手動の返金やキャンセルがたくさんあった、または金額が特に大きいものが 1 件ありました。

**対応**

- メッセージに書かれた操作者に直接聞く。キャンペーンの終了やシステム障害の補償でも、こうなることがあります。
- **本人がやっていないと言う**：そのアカウントが乗っ取られたものとして扱い（「新しい端末からログイン」の項目を参照）、該当する取引を 1 件ずつ確認してください。

## 冒頭に「⏱ Delayed: this alert is from …」とあるメッセージ

**意味**：これは前に起きたことの通知です。そのときはどのチャネルでも送れなかったため（LINE が止まっていた、または月の通数を使い切っていて、Telegram・Discord・メールも設定されていなかった…）、保管しておいて今届けています。

**対応**

- メッセージにある元の時刻を見て、その通知の内容どおりに対応する。起きたのはその時刻で、今ではありません。
- 後から届く通知が多いなら、通知の経路が不安定です。開発者に LINE の月の通数が足りているか見てもらい、2 つ目のチャネル（メール、Telegram、Discord）が設定されているか確認してください。

## 週 1 回の動作報告（Weekly check-in）

**意味**：問題なし。週に一度、監視がまだ動いていることを伝えるものです。

**気をつけるべきなのは、むしろ届かないとき**です。1 週間以上届かなければ、チェックが動いていません（定期実行が止まった、LINE のトークンが期限切れ、サーバーを作り直したときに入れ直していない）。開発者に見てもらってください。
また、メッセージの「Records go back to …」（記録の開始日）が急に最近の日付になったら、記録がリセットされたということなので、理由を確認してください。

### 「Code fingerprint（コード指紋）」の読み方

その文字列（`3f9a-0c1d-77b2-e4a8` のようなもの）は、サイトのすべてのプログラムファイルから計算したものです。どれか 1 本でも変わると、この文字列が変わります。
これはあなたの LINE に残り、サーバーに侵入した人には書き換えられません。だから**この動作報告のメッセージは削除しないでください**。

後ろに書いてあることを見るだけで大丈夫です：

| メッセージの内容 | すること |
|---|---|
| same as the last check-in | 何もしなくて大丈夫。この 1 週間、プログラムは変わっていません |
| was xxxx; N code-change notice(s) were sent in between | その N 回が全部自分たちのアップロードだったか思い出してください。そうなら問題ありません |
| was xxxx; N change(s) were written to the log but not sent | 開発者に記録を見てもらってください。たいていはサイトが自分で書き換えるファイルか、その日の通知が多すぎて止められたものです |
| 先頭に ⚠ があり「no code change is on record」とある | **その日のうちに対応。** プログラムが変わったのに監視が記録していない、つまり監視の記録が書き換えられた可能性があります。「バックドアがあるかもしれない」の項目のとおりに |

自分で確かめたいときは、ひとつ前の動作報告までさかのぼって 2 つの文字列を見比べれば、メッセージが本当のことを言っているかわかります。

### 「LINE messages this month: about N of M used」（今月の LINE の送信数）の行

LINE公式アカウントが月に送れるメッセージ数には上限があります（プランによって違います）。この行は週に一度ついでに LINE に問い合わせたもので、同じLINE公式アカウントから送ったすべてのメッセージ（お客さん向けのキャンペーン配信も含む）の数です。

- ⚠ がなければ：何もしなくて大丈夫です。
- **⚠ があり「about N of M」や「used up」とある**：使い切ると LINE からは何も届かなくなり、セキュリティ通知も同じです。どちらか、または両方をしてください：LINE Official Account Manager でプランを上げる。開発者に 2 つ目のチャネル（メール、Telegram、Discord。LINE で送れないときはそちらに届く）が設定されているか確認してもらう。
  Telegram と Discord は無料です。`line_min_level => 2` にすると、LINE は URGENT の通知だけに使われます。

### 「⚠ The outside check-in address has failed…」（外部チェックインの URL が続けて失敗）の行

**意味**：「定期実行が止まったら外部サービスが知らせる」設定をしているのに、そのサービスの URL につながりません。チェック自体は動いていますが、定期実行が止まっても誰も知らせてくれない状態です。

**対応**：開発者に設定の URL を確認してもらってください（貼り間違い？　そのサービスのアカウントはまだある？）。

## 外部サービス（LINE ではない）から「チェックインがない」と届いた

**意味**：外部チェックインを使っている場合、そのサービスから届きます（たいていメール）。サイトの定期チェックが、決めた時間を過ぎても報告していない、という知らせです。

**対応**

- まずスマホでサイトを開く。サイトも開けなければサーバーの問題なので、レンタルサーバー会社に連絡する。
- サイトは普通に開けて、チェックだけ止まっている：開発者に定期実行を見てもらう（サーバーの引っ越し、設定の変更、サーバー会社のメンテナンスはなかったか）。
- 誰も定期実行を触っていないのに止まった：軽く考えないこと。定期実行を止めるのも、監視を黙らせる方法の 1 つです。

## ふだんから準備しておくこと

何か起きてから探しても、たいてい間に合いません：

- **バックアップ**：毎日自動で取り、少なくとも 1 つは同じサーバー以外の場所に置く。年に 2 回は実際に戻してみて、本当に使えるか確かめる。
- **連絡先の一覧**：レンタルサーバー会社のサポート窓口、開発者の連絡先、使っている各サービスの管理画面の URL。サイトの管理画面の中だけでなく、スマホに。
- **パスワード**：1 人 1 アカウントで共有しない。全部 2 段階認証をオンに。辞めた人のアカウントはその日に停止。
- **アップデート**：システムやプラグインのセキュリティ更新は入れる。侵入のほとんどは、とっくに修正済みの古い穴を使っています。
