# 預防清單：在警報響之前先做的事

這個套件做的是「出事了讓你知道」。這份清單是另一半：讓事情比較不容易發生。
兩邊都要有，因為任何一道防護都可能失守。

（其中幾項是第一版公開後，網友回饋補充的，謝謝大家。）[English](hardening-checklist.md)／[日本語](hardening-checklist.ja.md)

## 一、每一項十分鐘，先做這些

**1. 上傳資料夾不能執行程式**

客人或店員上傳圖片的資料夾，只該放圖片和文件。最常見的入侵方式，就是把一支程式偽裝成圖片傳上來再去開它。
把那個資料夾設成「裡面的程式檔一律不給開」，這招就失效了。

Apache（多數虛擬主機）在該資料夾放一個 `.htaccess`：

```
<FilesMatch "\.(php\d?|phtml|pht|phar|inc|cgi|pl|py|sh)$">
    Require all denied
</FilesMatch>
```

nginx 沒有 `.htaccess`，要請主機商或工程師在設定裡對那個資料夾做同樣的事。
設好之後自己試一次：放一支測試用的 `.php` 進去，用瀏覽器開它，應該被拒絕；試完刪掉。
本套件的「上傳資料夾裡出現程式檔」警報是這一項的後援：萬一設定被人改掉，你會知道。

**2. 每個後台帳號都開兩步驟驗證（或通行金鑰）**

一人一個帳號，不共用。帳號名稱不要叫 `admin`。人離職當天就停用。

**3. 備份放在主機外面，而且真的還原過一次**

沒有試過還原的備份，等於不確定有沒有備份。

**4. 兩個從主機外面看的服務**

- 網站打不打得開：用外部的網站監看服務。
- 排程還有沒有在跑：把排程報到服務的網址填進本套件的 `ping_url`。

**5. 系統和外掛有安全更新就裝**

大部分入侵用的是早就有修補的舊漏洞。

## 二、在後台外面再加一道門

兩步驟驗證保護的是「帳號」：密碼被猜中也登不進去。
多一道門保護的是「整個後台」：沒通過的人連後台任何一頁都碰不到，包括萬一有漏洞的那一頁。兩者不衝突，可以都要。

**做法 A：在網站前面的服務加身分驗證**（例如 Cloudflare Access）

網站如果本來就接在這類服務後面，這只是加一個設定：指定後台的網址要先通過身分確認（可以用 Google 帳號，不一定要收驗證信）。
要注意：

- **還原真實 IP。** 接了之後，主機看到的連線來源會變成那個服務的 IP。主機或程式要改成讀它帶來的真實 IP，而且只在連線真的來自那個服務時才相信。
  沒做這一步，本套件通知裡的 IP 會全部一樣，「同一個 IP 太多次」的判斷也會亂掉。傳給 `loginFailed()`、`firewallBlocked()` 的 IP 要是還原後的那一個。
- **鎖住原始主機。** 知道主機真實位址的人可以繞過前面那一層直接連。主機要設成後台只接受那個服務轉來的連線。
- **放行機器呼叫的網址。** 金流、LINE、電話系統這類由別的系統來呼叫的網址不能擋。
- 先在測試環境做，把付款、訊息通知、排程都測過再上正式站。

**做法 B：用主機本身的「資料夾密碼保護」**

多數主機管理介面都有這個功能（對後台資料夾設一組帳號密碼，進任何一頁之前瀏覽器先跳出輸入框）。不用動網域設定，不對就關掉。
要注意：

- 密碼用很長的亂數，這道門本身通常沒有「猜錯幾次就鎖」。
- 同樣要放行機器呼叫的網址。
- **用真的手機試。** 手機瀏覽器、通訊軟體裡的內建瀏覽器、裝到桌面的網頁程式，對這種輸入框的支援不一樣。店員每天用手機開後台的話，先試過再全面啟用。

## 三、自己管整台主機的人（VPS）

- 遠端登入（SSH）不要對全世界開放：只用金鑰登入、用防火牆限制來源，或平常關閉、需要時從主機商的控制台進去。
- 租虛擬主機的人碰不到這一層，那是主機商在管，可以問他們有沒有做。

## 四、上傳功能的進階做法

如果網站前面有可以跑小程式的服務，可以讓上傳先經過它：在外面先檢查大小和格式，合格才轉給主機；主機再確認請求真的來自那一層，並且自己再檢查一次。
這是多一層，不是唯一一層。「看起來是圖片」的檢查擋不住把程式藏在真圖片後面的手法，真正的保險還是第一項。

## 五、放一個陷阱：誘餌金鑰（大約 10 分鐘，免費）

這個套件的每一種檢查，看的都是入侵者「改了什麼」。只「翻看」你的檔案、找密碼和金鑰的人，這些檢查都看不到。誘餌專門抓這種人。

1. 到 [canarytokens.org](https://canarytokens.org)（免費；程式碼在 github.com/thinkst/canarytokens）選 **「AWS Keys」**，
   填要收警告的 Email，和一段自己看得懂的備註（例如「商店主機、家目錄」）。它會給你一組假的金鑰。
2. 把它放在找密碼的人會去翻、但正常不會有人讀的地方：例如主機帳號家目錄裡的 `.aws/credentials` 檔，
   或是在真正的設定檔旁邊加一行 `# 舊的備份金鑰：AKIA… / …`。**絕對不要放在網站公開的資料夾裡**（網路上任何人都可能觸發它），
   也不要放在你們自己的程式會用到的地方。
3. 完成。沒有任何人有理由使用這組金鑰；哪天有人拿去試，那個服務就會寄信給你（要先經過 Amazon 的紀錄，大約晚 2～30 分鐘）：代表有人在翻你主機上的檔案。

這組金鑰是假的，什麼都打不開。那個服務只知道你的備註和你給它的 Email。

## 六、讓 Google 覺得網站被入侵時有人通知你

把網站加進 Google Search Console（免費），讓它寄信給老闆。它的「安全性問題」報告看到的是 Google 真正的爬蟲拿到的內容；
有些垃圾連結入侵只對 Google 自己的 IP 現身，從主機裡面檢查是騙不出來的。

## 這份清單取代不了什麼

偵測。上面每一項都在降低出事的機會，但沒有一項能保證。所以還是要有東西在出事的當天告訴你。
